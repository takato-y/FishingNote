## 背景

釣り場探し（REQ-014）とマイ釣り場の表示（REQ-015）には地図が要る。
アプリの中に地図を埋め込む方法と、端末の地図アプリに検索語や座標を渡す方法がある。

- 地図を埋め込むには、地図サービスの API キーと支払いの設定が要り、アプリが通信するようになる
- 無料の地図部品（osmdroid）は開発が終わっている
- 座標を付けない検索（`geo:0,0?q=…`）では、地図アプリが現在地の近くを探すとは限らない。試したところ、日本全体を表示して遠い候補を出した

## 決定

- アプリの中に地図を持たない。地図の表示と場所の検索は、端末の地図アプリに Intent で渡す
- 近くを探すときは、アプリがおおよその現在地（`ACCESS_COARSE_LOCATION`）を1回だけ取り、座標（小数4桁）と探す語を `geo:` の URI にして渡す。現在地は保存しない
- 現在地は、使える取り方（fused・network・GPS）すべてに同時に問い合わせ、最初に届いた位置を使う。10秒以内に届かない、権限が無い、位置情報がオフのときは、座標なしで渡し、理由を分けて知らせる
- 現在地や保存した釣り場を渡す先は Google マップに絞り、パッケージ名に加えて署名の証明書（SHA-256）を確かめる。入っていない・合わない端末では、既定のアプリに任せず、毎回アプリを選んでもらう

## 理由

- 地図を埋め込まなければ、API キー・支払い・通信が要らず、インターネットの権限を持たない方針（[ADR-0002](0002-インターネットの権限を持たずネット検索はブラウザに渡す.md)）を保てる
- おおよその位置の権限では省電力の取り方になり、Wi-Fi の無い海辺では取れないことがある。同時に問い合わせれば、取れた物から使える
- パッケージ名だけで信用すると、Google マップの無い端末で同じ名前を名乗る別のアプリに、選択画面なしで現在地を渡してしまう。署名まで確かめれば防げる。合わない場合も、毎回選んでもらう側に倒れるだけで、使えなくはならない

## 影響

- 地図アプリに渡した後の情報の扱い（検索履歴に残るなど）は、地図アプリ側の設定による。画面とプライバシーポリシーにその旨を書く
- 証明書の値は、端末に入っている Google マップから取り出した物である。Google が鍵を更新した場合は選択画面が出るようになるため、そのときに値を足す
- 釣り場の画面に、地図の上で場所を見ながら選ぶ機能は持てない。場所を保存するには、地図アプリの「共有」からこのアプリを選ぶ（REQ-016）
- GPS を併用できるのは API 31 以降である。API 30 以前は、Wi-Fi・基地局だけで現在地を取る
