## 背景

利用者は、釣り場の場所や釣果を他人に知られたくない（要件定義書 2.1）。
このため、データは端末の中だけに置き、アプリ自身は通信しないことを基本にした（REQ-021・REQ-022）。

一方で、道具の登録では、商品の型番や仕様を調べたい場面がある（REQ-006）。
ショッピングサイトの商品検索の仕組みをアプリから直接使えば、検索の結果をアプリの中に出せる。

## 決定

- アプリにインターネットの権限（`android.permission.INTERNET`）を持たせない
- 「ネットで調べる」は、道具の名前とメーカー・商品名から検索語を作り、検索のアプリ（`ACTION_WEB_SEARCH`）に渡す。受け取るアプリが無いときは、ブラウザで検索サイトの検索として開く
- 検索語が `http://`・`https://` で始まるときは、検索のアプリに渡さず、ブラウザで検索サイトの検索として開く
- 「メーカー・商品名」の候補は、前に登録した値と、アプリに持つ主なメーカー名の一覧（名前だけ）から出す。商品の型番や仕様はアプリに持たない
- 画面に「言葉は検索サイトに送られます」と示す

## 理由

- 商品検索の仕組みを直接使うと、アプリが通信するようになり、サービスへの登録と ID の埋め込みが要る。ブラウザの検索なら、登録も ID も要らず、アプリは通信しないままにできる
- 権限を持たなければ、アプリが通信しないことを、コードを読まなくても権限の一覧で確かめられる
- 検索のアプリは、検索語が URL の形だとそのサイトを開くことがある。検索サイトの検索として開けば、入力した URL のサイトを意図せず開かない
- 商品の型番や仕様は年ごとに変わり、アプリに持つとすぐに古くなる。メーカー名だけなら古くなりにくい

## 影響

- 検索の結果をアプリの中に取り込めない。利用者は検索の結果を見て、必要な値を自分で入れる
- 情報がアプリの外へ出る出口の1つになる（基本設計書 7章の出口2）。プライバシーポリシーに書く（配布するときは、Google Play のデータセーフティの申告にも書く）
- 将来、通信が要る機能（潮見表・天気など）を入れる場合は、この決定を見直す必要がある（いずれも現在は対象外）
