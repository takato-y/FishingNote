## 0. この文書の読み方

- 機能ID（FN）・画面ID（SCR）・アプリの外の画面（EXT）は、基本設計書（BD-001）の ID をそのまま使う
- コードの場所は `ファイル:行` で示す。パスは `app/src/main/java/com/example/fishingnote/` からの相対パスで書く（ビルドのタスクだけは `app/build.gradle.kts`）
- 画面に出る文言は、コードの文字列をそのまま「」で示す。`…` は実行時に値が入る部分を表す
- 障害が起きたときの対処は、障害対応手順書（OM-002）に同じエラーIDで書く

### 1.1 ERR-001 の文言

`BackupCrypto.ruleProblem`（`data/BackupCrypto.kt:74-87`）は、上から順に判定し、最初に当たった1つだけを返す。

| 順 | 条件 | 文言 |
|---|---|---|
| 1 | 12文字未満（`PASSWORD_MIN`） | 「パスワードは12文字以上にしてください」 |
| 2 | 0x21〜0x7E 以外の文字を含む（全角・空白・半角カナなど） | 「パスワードには半角の英数字と記号だけを使ってください（全角や空白は使えません）」 |
| 3 | よく使われるパスワードの一覧と一致（大文字・小文字を区別しない）、または英字を含み、よくある言葉に数字・記号を足した・文字を置き換えた・くり返しただけの物 | 「よく使われるパスワードです。推測されにくいものにしてください」 |
| 4 | 使っている文字の種類が5種類未満 | 「使っている文字の種類が少なすぎます。いろいろな文字を混ぜてください」 |
| 5 | 全部が同じ文字 | 「同じ文字だけのパスワードは使えません」 |
| 6 | 全部が数字 | 「数字だけのパスワードは推測されやすいため使えません。英字や記号も混ぜてください」 |
| 7 | 文字コードが1つずつ増える、または減る並びだけ | 「並んだ文字だけのパスワードは推測されやすいため使えません」 |
| 8 | 4文字以下の並びをくり返しただけ | 「同じ並びをくり返しただけのパスワードは推測されやすいため使えません」 |

5と8に当たるパスワードは、使う文字の種類が4種類以下になるため、必ず先に4で断られる。現行の判定順では、5と8の文言は画面に出ない（6.3）。

## 2. 共通の設計

### 2.1 画面の状態とスレッド

| 対象 | 方式 | 場所 |
|---|---|---|
| ViewModel の作り方 | `appViewModel` が `FishingNoteApp.repository` を渡して作る。ViewModel は画面の行き先（ナビゲーションのエントリ）ごとに持つ | `ui/common/Common.kt:104-107` |
| 一覧の状態 | `Repository` の `Flow` を `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), 初期値)` で `StateFlow` にする。初期値が `null` の物は「読み終える前」を表し、画面は何も描かない | 各 ViewModel |
| 保存・削除 | `viewModelScope.launch` の中で `Repository` の suspend 関数を呼び、終わったら `done()`（画面を閉じる）を呼ぶ | 各 ViewModel の `save`・`delete` |
| DB の読み書き | Room の suspend 関数と `Flow`。複数の表をまたぐ処理は `db.withTransaction` | `data/Repository.kt` |
| 編集中の入力 | `rememberSaveable` に置き、画面の回転やプロセスの終了で消えないようにする。読み込み済みの印（`loaded`）と最初の値（`initial`）も保存する | 各編集画面 |
| 重い処理 | ファイルの読み書きは `Dispatchers.IO`、JSON の検査・暗号化・復号・パスワードの判定は `Dispatchers.Default` | `ui/gear/GearScreens.kt` |
| 画面に結び付く処理 | `rememberCoroutineScope` で起動する。画面が閉じると止まる（バックアップの読み込み・復号・置き換え、現在地の取得） | `GearListScreen`・`SpotListScreen` |

### 2.2 入力の長さの上限

画面の入力欄は、入力のたびに `take(n)` で切り詰める。上限を超えた文字は入らない（メッセージは出さない）。

| 定数・値 | 値 | 使う欄 | 場所 |
|---|---|---|---|
| `NAME_MAX` | 40 | 道具・セット・釣り場の名前、釣行の場所、魚の種類、チェックリストといつもの持ち物に足す項目 | `ui/common/Common.kt:486` |
| `TEXT_MAX` | 100 | メーカー・商品名、号数などの仕様 | `ui/common/Common.kt:487` |
| `TEXT_MAX * 3` | 300 | 釣り場の「地図で探す住所・施設名」 | `ui/spots/SpotScreens.kt:350` |
| `MEMO_MAX` | 1,000 | 各メモ | `ui/common/Common.kt:488` |
| 6文字 | 6 | 「残り少ない」のしきい値、知らせる日数、魚の大きさ | `ui/gear/GearScreens.kt:675`・`:690`、`ui/log/LogScreens.kt:513` |
| 64文字 | 64 | パスワード（保存・読み込みとも同じ長さで切る） | `ui/gear/GearScreens.kt:852`・`:864`・`:1012` |

数字の欄は `parseNumber`（`ui/common/Common.kt:497-502`）で読む。表記をそろえて（`normalize`）前後の空白を除き、空なら `Empty`、`toDoubleOrNull` で読めない・負・NaN・無限なら `Invalid`、それ以外は `Value` とする。

### 2.3 数の増減の範囲

| 操作 | 範囲 | 場所 |
|---|---|---|
| 一覧の「＋」「－」（道具の数） | SQL で 0〜9999 に収める | `GearDao.addQuantity`（`data/Daos.kt:31-33`） |
| ワンタップ記録（魚の数） | SQL で 0〜99999 に収める | `TripDao.addCatchCount`（`data/Daos.kt:166-168`） |
| `Stepper`（共通部品） | 下限だけを持つ（`min`、既定は 0）。「＋」に上限は無い | `ui/common/Common.kt:204-221` |
| 道具の編集画面の「数」 | `Stepper` の下限 0。上限なし | `ui/gear/GearScreens.kt:672` |
| 釣行の編集画面の魚の「数」 | `Stepper` の下限 1。上限なし。候補の魚を押したときの加算（`addSpecies`）にも上限なし | `ui/log/LogScreens.kt:450-453`・`:520` |

編集画面の2つに上限が無いことは、6.1 の既知の制限とする。

## 3. 機能ごとの詳細

### FN-001 道具の登録・編集・削除

関連要件：REQ-001

| 区分 | 内容 |
|---|---|
| 入力 | 名前・種類・持っているか・メーカー・商品名・仕様・数・しきい値（文字）・巻き替え日（epoch day）・知らせる日数（文字）・メモ |
| 出力 | `gear` 表の1行（`GearDao.upsert`） |
| 例外 | ERR-028、ERR-029 |

1. `GearEditScreen`（`ui/gear/GearScreens.kt:580`）は、ID が 0 以外なら `vm.load` で読み、入力欄に入れてから `loaded` を true にする。最初の値（`initial`）は `editKey` で全項目をつないだ文字列とする
2. 保存を押すと、名前が空白だけなら ERR-028、しきい値が 0〜9999 の整数でなければ、知らせる日数が 0〜3650 の整数でなければ ERR-029（`intError`、`:619-621`）
3. 前後の空白を除いて `Gear` を作る。巻き替え日と知らせる日数は、種類がリール・ラインのとき（`GearCategory.hasLine`）だけ保存し、それ以外は null にする
4. `GearViewModel.save` → `Repository.saveGear`（`@Upsert`）。ID が 0 なら新しい行になる
5. 削除はゴミ箱のボタン → SCR-016「「…」を消します。セットからも外れます。」→ `Repository.deleteGear`。`set_gear` の行は外部キーの CASCADE で消える

### 4.2 暗号化した形式（.fnbk）

`BackupCrypto.encryptWith`（`data/BackupCrypto.kt:228-242`）が、改行（LF）で区切った6行のテキストを作る。最後の行の後にも改行を付ける。

| 行 | 内容 | 値 |
|---|---|---|
| 1 | 形式名 | `fishing-note-backup-encrypted`（`FORMAT`） |
| 2 | 版 | `1`（`VERSION`） |
| 3 | 繰り返し回数 | 書くときは `600000`（`ITERATIONS`） |
| 4 | 塩 | 16バイト（`SALT_BYTES`）を Base64 |
| 5 | 初期化ベクトル | 12バイト（`IV_BYTES`）を Base64 |
| 6 | 暗号文 | 4.1 の JSON（UTF-8）を暗号化し、末尾に16バイトの認証タグを付けた物を Base64 |

| 項目 | 方式 | 場所 |
|---|---|---|
| 鍵の作り方 | PBKDF2（`PBKDF2WithHmacSHA256`）。鍵の長さ 256 ビット | `data/BackupCrypto.kt:275-284` |
| 暗号 | `AES/GCM/NoPadding`、認証タグ 128 ビット（`TAG_BITS`） | `:235-238` |
| 追加の認証データ | `形式名\n版\n繰り返し回数` の UTF-8。見出しの3行を書き換えると復号できない | `:273` |
| 乱数 | 塩と初期化ベクトルは `SecureRandom` で毎回作る | `:143`・`:224-225` |
| Base64 | `java.util.Base64` の標準の符号化 | `:239`・`:252` |
| 書くときの確認 | パスワードが `ruleProblem` に当たれば `IllegalArgumentException`。繰り返し回数が受け付ける範囲外なら書かない（「繰り返し回数が範囲外です」） | `:231-234` |

`decrypt`（`data/BackupCrypto.kt:244-271`）は、鍵を作る（時間のかかる）前に次の順で確かめる。

1. 先頭の BOM・空白・改行を除き、行ごとに前後の空白を除いて空の行を捨てる。6行でない、または1行目が形式名でなければ ERR-017
2. 2行目が `1` でなければ ERR-017（対応していない版）
3. 3行目が整数で 100,000〜2,000,000（`ITERATION_RANGE`）でなければ ERR-017（設定が範囲外）
4. 4〜6行目が Base64 として読めない、塩が16バイトでない、初期化ベクトルが12バイトでない、暗号文が16バイト未満なら ERR-017
5. 暗号文から認証タグを除いた大きさが 5MB（`Backup.MAX_BYTES`）を超えれば ERR-011
6. 鍵を作って復号し、認証タグが合わなければ `WrongPasswordException`（ERR-018）

### 4.3 読み込みの検査（Backup.fromJson）

`Backup.fromJson`（`data/Backup.kt:62-111`）は、全部を検査し終えてから `BackupData` を返す。途中で止まった場合、データベースには何も書かない。

1. `JSONObject` として読めない（スタックの使い切りを含む）→ ERR-012
2. `format` が `fishing-note-backup` でない → ERR-012
3. `version` が無い・1 未満・1 を超える → ERR-012
4. 8つの表を読む。表が配列でない・無い → ERR-013
5. 整数の項目は `strictLong`・`strictInt` で読み、小数・±9.0×10^15 を超える数・文字で書いた数・int に収まらない数を止める → ERR-014
6. 種類が列挙の名前でない、日付が `yyyy-MM-dd` として読めない、必須の項目が無いなど、ほかの読み取りの失敗 → ERR-014（「バックアップの中身に読めない項目があります」）
7. `checkValues`（4.5）→ ERR-015
8. `checkReferences`（4.6）→ ERR-016

### 4.7 地図のリンクの条件（isMapUrl）

`domain/Rules.kt:199-225`。次をすべて満たす物だけを地図のリンクとして扱う。満たさない物は ERR-027 の扱いになる。

1. 前後の空白を除いて空でなく、途中に空白を含まない
2. `java.net.URI` として読め、スキームが `https`、利用者情報が無く、ポートが無いか 443
3. ホスト名（小文字にした物）が次の表と完全に一致し、パスが決まった形で始まる

| ホスト名 | パス |
|---|---|
| `maps.app.goo.gl`・`maps.google.com`・`maps.google.co.jp` | 制限なし |
| `goo.gl`・`google.com`・`www.google.com`・`google.co.jp`・`www.google.co.jp` | `/maps` と一致、または `/maps/` で始まる |

4. パスに `..`・`\`、エンコードした `.`・`/`・`\`（`%2e`・`%2f`・`%5c`、大文字・小文字を問わない）を含まない

## 6. 既知の制限と注意

### 6.1 編集画面の数に上限が無い

道具の編集画面の「数」（`ui/gear/GearScreens.kt:672`）と、釣行の編集画面の魚の「数」（`ui/log/LogScreens.kt:520`）、候補の魚を押したときの加算（`addSpecies`、`:450-453`）には上限が無い。`Stepper` が下限だけを持つためである（2.3）。保存（`saveGear`・`saveTrip`）でも範囲に収めない。

一方、バックアップの検査は道具の数を 0〜9,999、魚の数を 0〜99,999 に限る（4.5）。このため、編集画面でこれを超える数を保存すると、次のバックアップの保存が ERR-008（「保存できませんでした：バックアップの「道具」に、範囲外の値があります」または「…「釣果」…」）で止まる。一覧の「＋」「－」とワンタップ記録は SQL で範囲に収めるので、この問題は起きない。

範囲を超えた道具は、一覧の「－」を1回押すと `MIN(9999, MAX(0, quantity - 1))` により 9,999 になる（一覧に「＋」「－」が出る道具に限る）。魚の数は、釣行の編集画面で行を消して入れ直すか、「－」で範囲内に戻す。

### 6.2 画面を回したときに閉じる窓

`GearListScreen` の `askExport`（SCR-010）・`pendingEncrypted`（SCR-011）・`pendingImport`（SCR-012）は `remember` に置く。画面を回すとこれらの窓は閉じ、保存や読み込みをやり直すことになる。SCR-010 はパスワードを回転で保存される領域に置かないための意図した動作である（`ui/gear/GearScreens.kt:756`）。読み込みの途中の処理（ファイルの読み取り・復号・置き換え）も画面の `CoroutineScope` で動くため、回すと止まる。

### 6.3 表示されない文言

ERR-001 のうち「同じ文字だけのパスワードは使えません」と「同じ並びをくり返しただけのパスワードは推測されやすいため使えません」は、先に「使っている文字の種類が少なすぎます…」で断られるため、現行の判定順では画面に出ない（1.1）。断る範囲は変わらない。
