## 1. 目的と背景

釣りをする人は、竿・リール・ライン・ルアー・小物など、種類も数も多い道具を持つ。
道具の把握、出発前の持ち物の確認、釣果の記録は、それぞれ別のメモやアプリで行われることが多く、次の問題が起きている。

- 釣具店で、持っている道具を思い出せずに同じ物を二重に買う
- ラインの号数・長さ・巻き替えた日を忘れる
- 釣りの種類ごとに道具をそろえる手間が大きく、忘れ物をする
- 釣りの最中に記録を付けるのが面倒で、記録が残らない
- ログインが必要なサービスでは、アカウントを失うとデータも失う。また、釣り場の情報を他人に知られたくない

本システムは、道具の管理・出発前の準備・釣行の記録・釣り場探しを1つにまとめた Android アプリである。
目的は、上の問題を、ログインなし・端末の中だけのデータで解決することである。

## 2. 対象の利用者と使う場面

| 項目 | 内容 |
|---|---|
| 利用者 | 海や川で釣りをする個人。釣具店での買い物、出発前の準備、釣り場での記録をスマートフォン1台で行いたい人 |
| 使う場面 | 釣具店の店頭（持っている道具の確認）、自宅（道具の登録・持ち物の確認）、釣り場（釣果の記録・近くの釣り場探し） |
| 使う状態 | 釣り場では、片手・濡れた手・手袋をした手で操作し、日差しの下で画面を見る |
| 扱うデータ | 利用者が入力した道具・セット・持ち物・釣行と釣果・釣り場の記録。氏名・連絡先などは扱わない |

### 2.1 利用者の困りごとと要件の対応

| 困りごと | 対応する要件 |
|---|---|
| 釣具店で、持っている道具を思い出せずに二重に買う | REQ-002（検索）、REQ-001（欲しい物）、REQ-003（残りの少ない消耗品） |
| ラインの号数・長さ・巻き替え日を忘れる | REQ-001（仕様の記録）、REQ-004（巻き替えからの日数） |
| 釣りの種類ごとに道具をそろえるのが手間で、忘れ物をする | REQ-007（タックルセット）、REQ-008・REQ-009（チェックリスト） |
| 釣りの最中の記録が面倒 | REQ-011（ワンタップ記録）、REQ-012（候補からの入力） |
| ログインできずにデータを失う。釣り場を知られたくない | REQ-021・REQ-022（通信しない・端末の中だけ）、REQ-017・REQ-018（ファイルへのバックアップ） |

ラインの交換時期は、釣り方や保管の状態で変わり、一律の目安を決められない。
そのため、知らせるまでの日数は利用者が道具ごとに決める（空欄なら知らせない）。

## 4. 機能要件

### 4.1 道具

| ID | 要件 | 補足 |
|---|---|---|
| REQ-001 | 道具を登録・編集・削除できる | 項目は名前（必須）・種類（ロッド／リール／ライン／ルアー・エサ／小物・仕掛け／その他）・持っているか（持っている／欲しい物）・メーカー・商品名・号数などの仕様・数・「残り少ない」とするしきい値・ラインを巻き替えた日・知らせる日数・メモ。巻き替え日と知らせる日数は、リールとラインだけに出す。削除は確認してから行い、その道具は入っていたセットからも外れる |
| REQ-002 | 道具を言葉で検索し、「すべて」「残り少ない」「欲しい物」「巻き替え」で絞り込める | 検索は空白で区切った全部の語が、名前・メーカー・仕様・メモ・種類のどれかに含まれる物を出す。大文字と小文字、全角と半角、ひらがなとカタカナを区別しない。絞り込みには該当の件数を出す。言葉を入れ始めたら絞り込みを「すべて」に戻す |
| REQ-003 | 一覧から道具の数を増減できる | 対象は、しきい値を決めた道具と、種類が「ルアー・エサ」「小物・仕掛け」の道具（持っている物だけ）。減らした直後は「元に戻す」を出す |
| REQ-004 | ラインを巻き替えてからの日数を一覧に出し、利用者が決めた日数を超えたら「巻き替え時期」として目立たせる | 対象はリールとライン。未来の日付は0日として扱う。日数を決めていなければ知らせない |
| REQ-005 | 「メーカー・商品名」に途中まで入れると、候補を出す | 候補は最大6件。前に登録した値（新しい順）を先に、主な釣り具メーカーの名前を後に並べる。それぞれの中では、入れた言葉で始まる物を先にする |
| REQ-006 | 道具の名前とメーカー・商品名で、ネット検索を開ける（「ネットで調べる」） | 検索はアプリの外（検索のアプリ、無ければブラウザ）で行う。画面に「言葉は検索サイトに送られます」と示す |

### 4.2 セットと準備

| ID | 要件 | 補足 |
|---|---|---|
| REQ-007 | 釣りの種類ごとに、持っている道具をまとめたタックルセットを作成・編集・削除できる | 名前（必須）・メモ・入れる道具。道具が7件以上あれば、道具を言葉で絞り込める。セットを消しても道具は消えない |
| REQ-008 | セットの道具と「いつもの持ち物」から、持ち物チェックリストを作れる | セットを使わない作り方（いつもの持ち物だけ）もできる。道具は「名前（仕様）」の形にし、同じ名前は1つにまとめる。持っていない道具（欲しい物）は入れない。作り直すと今のチェックは消えるため、その旨を示す |
| REQ-009 | チェックリストの項目にチェックを付け外しでき、進み具合を示す | 全部のチェックを外す（確認あり）、今回だけの項目を足す、編集中に項目を消す（元に戻せる）ができる |
| REQ-010 | 「いつもの持ち物」を追加・削除できる | 初めて起動したときだけ、例（ライフジャケット・プライヤーなど8件）を入れる。消した直後は「元に戻す」を出す |

### 4.3 記録

| ID | 要件 | 補足 |
|---|---|---|
| REQ-011 | 魚のボタンを押すたびに、今日の記録へその魚を1匹足せる（ワンタップ記録） | ボタンは前に記録した魚の多い順に6つ（足りなければよく釣れる魚で埋める）。ほかの魚は名前を入れるか、前に記録した魚を押して足す。今日の記録が無ければ作り、前回使ったセットを入れる。押した直後は「元に戻す」を出す |
| REQ-012 | 釣行を詳しく記録・編集・削除できる | 日付・場所・使ったセット・メモと、釣れた魚（種類・最大の大きさ・数）。場所と魚の種類は前の入力から選べる。新しい記録には前回使ったセットを最初から選んでおく |
| REQ-013 | 今年の釣果を集計して示す | 今日の数・今年の釣れた数・釣行回数・よく釣れた魚（上位3）・セットごとの釣果・月ごとの釣れた数・今年いちばん大きかった魚 |

### 4.4 釣り場

| ID | 要件 | 補足 |
|---|---|---|
| REQ-014 | 現在地の近くの釣り場を、地図アプリで探せる | 「釣り公園」「海釣り施設」「漁港」「釣り桟橋」「管理釣り場」「釣具店」「釣り船」の7つの語から選ぶ。おおよその現在地を付けて地図アプリに渡す。現在地を取れないときは現在地なしで渡し、理由を示す |
| REQ-015 | 気に入った釣り場を保存・編集・削除し、地図アプリで開ける | 名前（必須）・地図で探す値（住所・施設名・緯度経度・地図のリンク）・メモ。保存した釣り場が1件以上あれば、釣り場の画面で「近くを探す」より上に出す |
| REQ-016 | 地図アプリの「共有」から場所を受け取り、釣り場として保存できる | 受け取った文から名前と地図の値を取り出して、釣り場の保存画面に入れる。保存は利用者が押したときだけ行う。編集中に届いた場合は、一覧に戻ってから開く |

### 4.5 バックアップとアプリの情報

| ID | 要件 | 補足 |
|---|---|---|
| REQ-017 | 全データをファイルに保存できる（バックアップ） | 保存先は利用者が選ぶ。「パスワードで守る」を選べ、最初はオンにする。オフのときは誰でも読める形になることを、その場で示す |
| REQ-018 | バックアップのファイルから、全データを戻せる | 全件の置き換えとし、実行前に中身の件数を示して確認する。パスワードで守られていないファイルは、その旨も示す。読み込みに失敗したときは、今のデータを変えない |
| REQ-019 | 最後のバックアップから30日を超えた（または一度も無い）ときは、道具の一覧の上で保存を勧める | 押せばその場で保存に進める |
| REQ-020 | アプリの版、プライバシーポリシー、使っている外部ライブラリのライセンスを、アプリの中で読める | 道具の画面のメニュー「このアプリについて」から開く |

## 5. 非機能要件

### 5.1 通信とデータの置き場所

| ID | 要件 | 補足 |
|---|---|---|
| REQ-021 | アプリ自身は通信しない。インターネットの権限を持たない | 情報がアプリの外へ出るのは、利用者の操作による次の3つだけとする：①地図アプリへの受け渡し（REQ-014・REQ-015）、②検索のアプリ・ブラウザへの受け渡し（REQ-006）、③利用者が選んだ保存先へのバックアップ（REQ-017）。広告・利用状況の分析・不具合の自動報告の仕組みは組み込まない |
| REQ-022 | データは端末の中の、このアプリ専用の保存場所だけに置く。ログインを求めない | Android 標準の自動バックアップと、新しい機種への引っ越し（端末間の移行）からは、全領域を除外する。データの移し替えは REQ-017・REQ-018 で行う |
| REQ-023 | 位置情報は、おおよその位置だけを、利用者が探すボタンを押したときだけ使い、保存しない | 詳しい位置（ACCESS_FINE_LOCATION）と、アプリを使っていないときの位置は使わない。権限は探すボタンを初めて押したときに求める。現在地や保存した釣り場を渡す先は Google マップ（署名の証明書まで確かめる）に絞り、入っていない端末では毎回アプリを選んでもらう |

### 5.2 屋外での操作

| ID | 要件 | 補足 |
|---|---|---|
| REQ-024 | 片手・濡れた手・手袋でも押し分けられる大きさにする | 押す対象は 56dp 以上（選択肢のチップを含む。チップの間隔は 12dp）。主なボタンは高さ 60dp、ワンタップ記録の魚のボタンは高さ 76dp。本文の文字は 18sp |
| REQ-025 | 押した結果で、画面の上の物の位置を動かさない | 続けて押したときに、指の下へ別の物が来て押し間違えるのを防ぐ。チェックリストの並び、ワンタップ記録の魚のボタンの並びと「元に戻す」の位置、一覧の追加ボタンの位置が対象（詳細は基本設計書 5.4） |
| REQ-026 | 消す・減らす操作は、その場で取り消せるか、確認してから行う。編集中の入力を確認なしに失わない | 1件単位の軽い操作（数を減らす・チェックリストから外す・いつもの持ち物を消す・ワンタップ記録）は「元に戻す」を出す。道具・セット・記録・釣り場の削除と、チェックリストの作り直し・全部外す・バックアップからの置き換えは確認を出す。編集画面で変更したまま戻るときは確認する |
| REQ-027 | 画面の回転などで画面が作り直されても、入力中の内容と操作の状態を失わない | 編集中の入力、ワンタップ記録の「元に戻す」、チェックリストの並び、バックアップの保存の結果の知らせが対象。パスワードは除く（REQ-030） |

### 5.3 入力の上限と外から入る値

| ID | 要件 | 補足 |
|---|---|---|
| REQ-028 | 入力の長さと数の範囲に上限を設ける | 画面で入れる文字は、名前・場所・魚の種類・持ち物は40文字、メーカー・仕様は100文字、地図で探す値は300文字、メモは1000文字まで。しきい値は0〜9999、知らせる日数は0〜3650日、魚の大きさは500cmまで。一覧の増減とワンタップ記録で変わる数は、道具は0〜9999、魚は0〜99999に収める |
| REQ-029 | アプリの外から入る値（共有で届いた文・バックアップのファイル）を検査し、範囲外の物は受け取らない | 共有は2000文字以内。見えない文字は取り除く。地図のリンクとして扱うのは、https・決まったホスト・決まったパスの物だけ。バックアップは5MB以内、表ごとの件数・ID の重複・文字の長さ・数の範囲・日付・表どうしのつながりを確かめ、外れていたら何も変えずに止める。書き出す前にも同じ検査を通す |

### 5.4 バックアップの安全性

| ID | 要件 | 補足 |
|---|---|---|
| REQ-030 | パスワードで守るバックアップは、推測されにくいパスワードを使った場合に、パスワードを知らない人が読めず、書き換えにも気づける形に暗号化する。パスワードは推測されにくい物だけを受け付ける。パスワードを扱う窓では、画面の撮影と、コピー・切り取りの経路を止める | 鍵はパスワードから作る（端末の鍵保管庫は使わない）。半角の英数字と記号で12文字以上とし、よくある言葉やその変形、強さの見積もりで一番上の段階に届かない物は断る。アプリが作るパスワード（19文字）をおすすめとして先に出す。パスワードを扱う窓では、画面の撮影・コピー・切り取りを止め、表示したパスワードは、アプリを離れたとき・窓が操作の対象でなくなったとき・表示から1分後に伏せ直す。パスワードは画面の回転で保存される領域に置かない |

### 5.5 アクセシビリティと品質

| ID | 要件 | 補足 |
|---|---|---|
| REQ-031 | 色だけに頼らず、読み上げでも操作できるようにする | 選んだチップは色に加えて印（チェック）を出す。欲しい物は「【未所持】」と枠でも分ける。アイコンだけのボタンには読み上げの名前を付ける（例：「スナップを1つ減らす」）。グラデーションの上の白い文字は、コントラスト 4.5:1 以上にする。文字を大きくした設定でも、ボタンの文字が切れないようにする |
| REQ-032 | 判定と集計の処理は、画面から切り離して単体テストで確かめられる構造にする | 巻き替え時期・残りの少なさ・検索・チェックリストの作成・集計・地図の値の判定などは、状態を持たない関数にまとめる |
| REQ-033 | プライバシーポリシーは1つの原稿から作り、公開する文とアプリの中の文をずらさない | 配布用のビルドは、原稿に未記入の欄が残っている、またはパッケージ名が仮のままの場合に止める |

## 6. 前提

- 地図の表示と場所の検索は、端末に入っている地図アプリが行う。地図アプリに渡した後の情報の扱いは、地図アプリ側の設定による
- 「ネットで調べる」の検索は、端末に入っている検索のアプリまたはブラウザが行う
- バックアップの保存先（端末の中のフォルダ・クラウドの保存場所）は、Android の保存先を選ぶ画面で利用者が選ぶ
- 強さの見積もりは推測に要る回数の見積もりであり、パスワードの強さを保証するものではない

## 7. 対象外

- 写真の記録
- アプリの中の地図（地図は地図アプリで表示する。[ADR-0001](adr/0001-地図はアプリに持たず地図アプリに渡す.md)）
- 詳しい位置（ACCESS_FINE_LOCATION）と、アプリを使っていないときの位置の取得
- 潮見表・天気の自動取得
- アカウントと、端末をまたいだ同期
- 通知（巻き替え時期・残りの少なさは、アプリの一覧の中でだけ示す）
- ショッピングサイトの商品検索の仕組みを、アプリから直接使うこと（[ADR-0002](adr/0002-インターネットの権限を持たずネット検索はブラウザに渡す.md)）
